# Test script

This script describes a fuzzer for test MLIR compiler infrastructure.
It tests the MLIR compiler infrastructure, and may collect the coverage information per hour.


# External tools

This script relay on some external tools:

+ `mlir-opt`: the mlir compiler we what to test.

+ `CreateNode`: a mutator that generate a new oepration in existing mlir program and output a new mlir program.
Usage: `CreateNode <old_program> <new_program>`

+ `DeleteNode`: a mutator that randomly delete an existing operation from an mlir program and output a new mlir program. 
Usage: `DeleteNode <old_program> <new_program>`

+ `ReplaceDataEdge`: a mutator that randomly change the operand of random operation with the given probability, and output a new mlir program. 
Usage: `ReplaceDataEdge --operand-prob 0.1 <old_program> <new_program>`

+ `ReplaceControlEdge`: a mutator that randomly take a piece of code out of the current control related operation, and output a new mlir program. 
Usage: `ReplaceControlEdge <old_program> <new_program>`

+ `mlir-func-call`: a mutator that call one function from an mlir program in another function in another mlir program, and finally output a new mlir program.
Usage: `mlir-func-call <src_program> <dest_program> <new_program>`

+ `mlir-func-fuse`: a mutator that fuse one function from an mlir program into another function in another mlir program, and finally output a new mlir program.
Usage: `mlir-func-fuse <src_program> <dest_program> <new_program>`

The default value of these tools are in the environment vairbale PATH.

Make the path of above external tools configurable.

# Configuration

- duration: integer, to control the overall main process. Terminate the main process when time spent exceeds the duration.
- collect_cov_hour: bool, to control whether collect coverage per hour.
- collect_bug_hour: bool, to control whether collect bug number per hour.
- collect_pass_trigger: bool, to control whether collect the pass triggering.
- mlir_base: str, the path of MLIR directory to be collected.

# Input


## Seeds


`seeds`: a set of existing seeds, each of which has two files: `xxx.mlir` and `xxx.command.txt`.
xxx.mlir is the mlir program, and xxx.command.txt is a file that each line is the pass pipeline that can modify this program.



## Prob

A file that record the probability to select the mutators, the format and default value is:
```
CreateNode=1
DeleteNode=1
ReplaceDataEdge=1
ReplaceControlEdge=1
mlir-func-call=20
mlir-func-fuse=20
```

# Output

None

## `mutation` function
- Aim: conduct mutate and generate a new testcase.
- Input: 
	- mutator: Required, the mutator wrapper function.
	- testcase1: Required, the first mlir file.
	- testcase2: Optional, the second mlir file.
- Output: 
	- new_testcase: the mutated testcase. None if mutation fails.
- Detail: 
	```python
	if mutator in [CreateNode, DeleteNode, ReplaceDataEdge, ReplaceControlEdge]:
		new_program = mutator(testcase1.program)
		new_pass = testcase1.pass
	elif mutator in [mlir-func-call, mlir-func-fuse]:
		new_program = mutator(testcase1.program, testcase2.program)
		new_pass = testcase1.pass + testcase2.pass
	else:
		assert False
	if new_program is None:
		return None
	new_testcase = TestCase(new_program, new_pass)
	return new_testcase
	```

## `test` function

- Aim: test the mlir-opt
- Input: testcase
- Output: 
	- test result, which can be:
		- error: mlir-opt print "error: " when compiling this mlir program.
		- crash: mlir-opt print "please report a bug" message in stderr when compiling this mlir program.
		- triggered: the mlir program is modified by the given pass pipeline.
		- not-triggered: the mlir program is remain unchanged before and after compilation.
- Detail:
	```
	# The overall test method is simple, just like the following process
	```
